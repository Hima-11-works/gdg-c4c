AIR HEALTH

A working prototype for exploring hyper-local air-quality signals in Indian cities through available ground, citizen, satellite, and weather inputs.

Flutter apps Gemini advisory photo analysis H3 spatial grid FastAPI + PostGIS React + MapLibre

Prototype scope: source coverage varies; model outputs are experimental; no production deployment is claimed.

The Problem

Local events can fall between monitors

A city-wide reading is valuable, but does not describe every neighborhood and hour.
WHY GRANULAR DATA

Monitoring gaps

Ground stations provide important ambient measurements, while local events may happen away from a station.

Complementary evidence

Citizen reports, low-cost sensors, satellite products, and weather data each add context with different coverage and limitations.

Signals are not interchangeable

Satellite column products and thermal detections are not surface PM2.5 measurements. Each source needs its own timestamp, provenance, and interpretation.

Need for coordination

Reviewers need a shared view of evidence and uncertainty before they decide whether an event needs follow-up.

AI & Data Stack

Narrow AI role, visible data limits

Gemini assists image review; it does not make the pollution or response decision.
IMPLEMENTED COMPONENTS

Gemini image observations

Returns structured, advisory observations from a submitted photo for a person to review.

  • Cannot infer AQI or pollutant concentration from an image.
  • Cannot confirm a source, approve a report, or dispatch responders.

Citizen media handling

Backend image processing strips metadata before reviewer access.

Environmental inputs

Source adapters include OpenAQ, Copernicus Data Space Ecosystem, NASA FIRMS, and Open-Meteo where configured.

Spatial application

FastAPI, PostgreSQL/PostGIS, H3, React, MapLibre, and Flutter clients support the prototype workflow.

Candidate Review

Investigate a signal; do not assume its source

The dashboard presents evidence for human review.
HUMAN IN THE LOOP

Evidence sources

  • Satellite-derived context when available.
  • NASA FIRMS thermal detections when available.
  • Citizen reports and sensor readings when present.

Candidate is not confirmation

A candidate can be incomplete, stale, or wrong. The reviewer sees available provenance and records a decision.

The system does not promise zero false alarms and does not automatically dispatch responders.

Forecast Inspection

Inspect a published corridor run

Configured route geometry and backend forecasts are shown with run provenance.
MODEL OUTPUT

What is displayed

  • Latest published forecast when a run exists.
  • Run mode, issue time, method, and input references.
  • Observed-data evaluation status and limitations.

Geometry and scope

Corridor geometry is illustrative; it is not an authority-approved logistics route.

This view does not schedule freight, predict visibility or traffic delays, or provide driver medical guidance.

Accuracy

A run without sufficient observed labels does not establish real-world forecast accuracy.

Citizen Companion

Report events and compare estimates

Environmental awareness, not medical or relocation advice.
FLUTTER APP

Field reports

Submit smoke and fire observations with optional photo evidence. Metadata is removed by backend media processing before review.

Sensitivity preference

User-selected settings adjust exposure-alert thresholds. They do not diagnose or provide condition-specific clinical advice.

Nearby estimates

Compare available current and short-horizon AQI estimates for nearby cells.

Use with care

Estimates may be incomplete or stale. They are not safety ratings or recommendations to relocate. Unresolved place names may show a shortened cell label.

Incident Workflow

A simulator with persistent backend records

Demonstrates incident status changes without contacting emergency services.
SIMULATION

Example lifecycle

REPORTED → ASSIGNED → ACKNOWLEDGED → EN ROUTE → ON SCENE → RESOLVED

Status transitions persist in the configured backend.

Clear boundary

The app is labeled as a simulation. It does not contact emergency services, send public alerts, or dispatch physical units.

Any optional authority webhook is a separate backend configuration and should be shown only when verified.

Federation Experiment

Local client and aggregator workflow

A prototype demonstration, not a network of participating state agencies.
EXPERIMENTAL

What runs

A single-process partition demo and an optional multi-process client/aggregator workflow.

Demo inputs may be synthetic or test data; participant identities are not independently verified as agencies.

What it does not prove

  • Parameter exchange is not a privacy guarantee.
  • Differential privacy and secure aggregation are not established.
  • No national predictive accuracy or agency deployment is claimed.
Implementation Status

Working prototype, bounded claims

Run and evaluate the software locally; source coverage is configuration-dependent.

Next Steps
